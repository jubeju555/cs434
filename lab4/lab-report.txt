Task 1: Idle Scan
==================================================

Environment and roles:
- A: Windows 7 zombie, 192.168.43.138
- B: Kali attacker, 192.168.43.128
- C: Kali target, 192.168.43.129
- All hosts were on subnet 192.168.43.0/24
- Connectivity verified with ping between all hosts
- Windows firewall disabled on A

Q1. Setup for the attack
The idle scan used three hosts:
- A (Windows) as the zombie with predictable IP ID behavior
- B (Kali) as the attacker running hping3
- C (Kali) as the target host

Commands on B:
- hping3 -r 192.168.43.138
- hping3 192.168.43.129 -a 192.168.43.138 -S -p 80 -c 5
- hping3 192.168.43.129 -a 192.168.43.138 -S -p 22 -c 5

Q2. Attack results
- Initial probing of A showed predictable +1 style IP ID increments.
- Probing open port 80 produced larger IP ID jumps (often +2 or more).
- Probing closed port 22 produced near-baseline increments (about +1).
- On C, packets appeared to originate from A due to source spoofing.
- Spoofed scan output on B can show 100 percent packet loss, which is expected because responses return to A, not B.

Q3. Interpretation
- Initial probing: IP ID increases by about +1 each probe.
- Open port probing: larger jumps due to extra traffic caused by spoofed interaction.
- Closed port probing: near-baseline increments.
- Offending host from target perspective: A (192.168.43.138).

Conclusion:
Idle scan succeeded using IP ID side-channel inference instead of direct scan responses.

Task 2: ARP Poisoning
==================================================

Goal:
Perform ARP poisoning MITM between A and C using B with ettercap.

Attack command on B:
- echo 1 > /proc/sys/net/ipv4/ip_forward
- ettercap -T -M arp /192.168.43.138/ /192.168.43.129/

Q4. ARP cache before poisoning
Commands used:
- A (Windows): arp -a
- B (Kali): arp -an
- C (Kali): arp -an

Observed MAC addresses:
- A (192.168.43.138): 00:50:56:29:31:6d
- B (192.168.43.128): 00:0c:29:67:dd:23
- C (192.168.43.129): 00:0c:29:5f:ac:00

Observed ARP entries before attack:
- A: 192.168.43.128 -> 00-0c-29-67-dd-23, 192.168.43.129 -> 00-0c-29-5f-ac-00
- B: 192.168.43.138 -> 00:50:56:29:31:6d, 192.168.43.129 -> 00:0c:29:5f:ac:00
- C: 192.168.43.128 -> 00:0c:29:67:dd:23, 192.168.43.138 -> 00:50:56:29:31:6d

Answer:
Before poisoning, ARP caches showed correct IP-to-MAC mappings.

Q5. Meaning of -M in ettercap
- -M enables man-in-the-middle mode.
- -M arp selects ARP poisoning as the MITM method.
- -T selects text interface mode.

Q6. ARP cache after poisoning
Observed change on A after attack:
- 192.168.43.129 changed from C MAC (00-0c-29-5f-ac-00) to B MAC (00-0c-29-67-dd-23)

Answer:
ARP hijacking was successful. A mapped C's IP to B's MAC, indicating MITM redirection.
